# Q38. 얕은 복사와 깊은 복사란 무엇인가요?

## 1. 데이터 복사란?

데이터를 복사한다는 것은 **원본 데이터와 같은 내용을 가진 새로운 데이터를 만드는 것**을 의미합니다.

자바스크립트에서는 데이터 타입에 따라 복사되는 방식이 다릅니다.

| 구분 | 종류 | 복사 방식 |
| --- | --- | --- |
| **원시 타입** | `number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint` | **값 자체**가 복사됨 |
| **참조 타입** | `Object`, `Array`, `Function` 등 | 값이 아닌 **메모리 주소(참조)** 가 복사됨 → 같은 값을 참조 |

```js
// 원시 타입: 값 자체가 복사됨
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 (원본 영향 X)

// 참조 타입: 메모리 주소가 복사됨
const obj1 = { name: "Kim" };
const obj2 = obj1;
obj2.name = "Lee";
console.log(obj1.name); // "Lee" (원본도 변경됨!)
```

그래서 참조 타입을 복사할 때는 **얕은 복사**와 **깊은 복사**라는 개념을 알아야 합니다.

---

## 2. 얕은 복사 (Shallow Copy)

### 개념

- 객체(또는 배열)를 복사할 때 **가장 상위 레벨의 값만 복사**하는 방식
- 객체 내부에 **중첩된 객체나 배열은 새로운 메모리 공간에 복사되지 않고, 메모리 주소를 공유**함
- 따라서 중첩된 값을 수정하면 **원본도 함께 변경**됨

```js
const original = {
  name: "Kim",
  info: { age: 25 },
};

const copy = { ...original };

copy.name = "Lee";      // 최상위 값 → 원본 영향 X
copy.info.age = 30;     // 중첩 객체 → 원본 영향 O

console.log(original.name);     // "Kim"
console.log(original.info.age); // 30 😱
```

### 구현 방법

| 방법 | 설명 |
| --- | --- |
| **스프레드 문법** (`...`) | 객체나 배열의 요소를 펼쳐서 새로운 객체/배열에 담는 문법 |
| **`Object.assign()`** | 하나 이상의 출처 객체의 속성을 대상 객체에 복사하고, 대상 객체를 반환하는 메서드 |
| **`Array.prototype.slice()`** | 배열의 지정한 범위(인자가 없으면 전체)를 잘라 새로운 배열로 반환하는 메서드 (원본 배열은 변경 X) |
| **`Array.prototype.concat()`** | 기존 배열에 인자로 받은 배열이나 값을 합쳐 새로운 배열을 반환하는 메서드 (원본 배열은 변경 X) |

```js
const obj = { a: 1, b: { c: 2 } };
const arr = [1, 2, [3, 4]];

// 객체
const copy1 = { ...obj };
const copy2 = Object.assign({}, obj);

// 배열
const copy3 = [...arr];
const copy4 = arr.slice();
const copy5 = [].concat(arr);
```

### 언제 사용할까?

- **중첩된 객체가 없는 경우**
- 중첩된 객체가 변경되어 **원본에 영향을 주어도 문제가 없는 경우**

## 3. 깊은 복사 (Deep Copy)

### 개념

- 객체 또는 배열을 복사할 때 **내부에 있는 모든 중첩된 객체와 배열까지 새로운 메모리 공간에 재귀적으로 복사**하는 방식
- 원본과 복사본이 **완전히 독립적**이므로, 한쪽이 변경되어도 다른 쪽에 전혀 영향을 주지 않음

### 방법 1: `JSON.parse(JSON.stringify(object))`

자바스크립트 객체를 **JSON 문자열로 변환**(`JSON.stringify`)한 뒤, 그 문자열을 **다시 자바스크립트 객체로 변환**(`JSON.parse`)하여 새로운 메모리 공간에 완전히 독립적인 객체를 생성합니다.

```js
const original = { name: "Kim", info: { age: 25 } };
const copy = JSON.parse(JSON.stringify(original));

copy.info.age = 30;
console.log(original.info.age); // 25 (원본 영향 X)
```

#### ⚠️ 한계점

1. **Date 객체** → ISO 형식의 **문자열로 변환**되어 Date 객체의 메서드를 사용할 수 없음
2. **함수** → 문자열로 변환하는 과정에서 **제거됨**
3. **`undefined` 값을 가진 속성** → 변환 과정에서 **속성 자체가 제거됨**
4. **순환 참조** → 객체가 자기 자신을 참조하는 경우 **오류(TypeError) 발생**
5. **Map, Set 등 내장 객체** → **빈 객체(`{}`)** 로 변환되어 데이터가 사라짐

```js
const obj = {
  date: new Date(),
  fn: () => console.log("hi"),
  value: undefined,
  map: new Map([["key", "value"]]),
  set: new Set([1, 2, 3]),
};

console.log(JSON.parse(JSON.stringify(obj)));
// { date: "2026-11-22T03:00:00.000Z", map: {}, set: {} }
// → date는 문자열, fn·value는 사라짐, map·set은 빈 객체

const circular = { name: "Kim" };
circular.self = circular;
JSON.stringify(circular); // ❌ TypeError: Converting circular structure to JSON
```

### 더 안전한 깊은 복사 방법

#### ① 재귀 함수 직접 구현

```js
function deepCopy(obj, seen = new WeakMap()) {
  // 원시 타입이나 null은 그대로 반환
  if (obj === null || typeof obj !== "object") return obj;

  // 순환 참조 처리
  if (seen.has(obj)) return seen.get(obj);

  // Date 처리
  if (obj instanceof Date) return new Date(obj);

  const copy = Array.isArray(obj) ? [] : {};
  seen.set(obj, copy);

  for (const key of Object.keys(obj)) {
    copy[key] = deepCopy(obj[key], seen);
  }
  return copy;
}
```

> Map, Set, 클래스 인스턴스 등 처리해야 할 케이스가 많아질수록 구현이 복잡해짐

#### ② 외부 라이브러리 사용 – Lodash의 `_.cloneDeep()`

```js
import _ from "lodash";

const copy = _.cloneDeep(original);
```

- Date, Map, Set, 순환 참조 등 다양한 케이스를 안정적으로 처리
- 단, 외부 의존성이 추가됨

#### ③ `structuredClone()` API 사용

```js
const copy = structuredClone(original);
```

- 최신 브라우저(및 Node.js 17+)에서 기본 제공하는 깊은 복사 API
- Date, Map, Set, 순환 참조 등을 지원
- 단, **함수나 DOM 노드는 복사할 수 없음** (`DataCloneError` 발생)

### 방법 비교

| 방법 | Date | 함수 | undefined | 순환 참조 | Map / Set |
| --- | :---: | :---: | :---: | :---: | :---: |
| `JSON.parse(JSON.stringify())` | ❌ | ❌ | ❌ | ❌ | ❌ |
| `_.cloneDeep()` | ✅ | ❌ (빈 객체로 반환) | ✅ | ✅ | ✅ |
| `structuredClone()` | ✅ | ❌ (에러) | ✅ | ✅ | ✅ |

## 4. 얕은 복사 vs 깊은 복사 정리

| 구분 | 얕은 복사 | 깊은 복사 |
| --- | --- | --- |
| 복사 범위 | 최상위 레벨만 | 중첩된 객체/배열까지 전부 |
| 중첩 객체 | 메모리 주소 공유 | 새로운 메모리에 복사 |
| 원본 영향 | 중첩 값 수정 시 영향 O | 영향 X |
| 장점 | 간단하고 빠름, 메모리 효율적 | 데이터 무결성 보장 |
| 단점 | 원본이 의도치 않게 변경될 수 있음 | 성능·메모리 비용이 큼 |
| 구현 | `...`, `Object.assign()`, `slice()`, `concat()` | `JSON` 방식, 재귀 함수, `_.cloneDeep()`, `structuredClone()` |

## 🎤 모의 면접

### Q1. 자바스크립트에서 원시 타입과 참조 타입을 변수에 할당할 때, 값이 복사되는 방식의 차이는 무엇인가요?

> 원시 타입은 변수에 할당할 때 **값 자체가 복사**되기 때문에, 복사한 변수를 수정해도 원본에는 영향이 없습니다.
>
> 반면 참조 타입은 값이 아닌 **메모리 주소(참조)가 복사**되기 때문에, 두 변수가 **동일한 객체를 가리키게** 됩니다. 그래서 복사된 객체의 값을 수정하면 원본 객체도 함께 수정됩니다.

### Q2. 얕은 복사와 깊은 복사의 차이점과 각각의 장단점, 그리고 깊은 복사를 안전하게 구현하는 방법에는 어떤 것들이 있나요?

> 얕은 복사는 **최상위 레벨의 값만 복사**하고, 내부의 중첩된 객체나 배열은 메모리 주소를 공유합니다. 반면 깊은 복사는 **최상위뿐 아니라 내부의 중첩된 객체와 배열까지 모두 새로운 메모리 공간에 복사**합니다.
>
> 얕은 복사는 구현이 간단하고 빠르지만, 중첩된 값을 수정하면 원본까지 변경될 수 있다는 단점이 있습니다. 깊은 복사는 원본과 완전히 독립적이어서 **데이터 무결성을 지킬 수 있지만**, 모든 데이터를 복사하므로 **성능과 메모리 사용량을 고려**해야 합니다.
>
> 깊은 복사를 `JSON.parse(JSON.stringify())`로 구현하면 Date, 함수, undefined, 순환 참조, Map/Set 등을 제대로 처리하지 못하는 한계가 있습니다. 그래서 더 안전하게 구현하려면 **재귀 함수를 직접 구현**하거나, **Lodash의 `_.cloneDeep()` 같은 외부 라이브러리**를 사용하거나, 최신 브라우저에서 제공하는 **`structuredClone()` API**를 사용할 수 있습니다.
