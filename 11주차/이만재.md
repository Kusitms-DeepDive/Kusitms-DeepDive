### Q38 얕은 복사와 깊은 복사란 무엇인가요?

---

#### **책을 읽기 전 혼자 답해보기**

> 얕은 복사는 최상위 값만 복사하고 중첩된 객체는 메모리 주소를 그대로 공유한다. 그래서 A를 얕은 복사한 B는 A의 중첩된 객체가 변경되면 B의 값도 같이 변경된다. 원시 타입 속성은 값이 복사되므로 독립적이다.
하지만 깊은 복사는 아예 다른 메모리 주소에 저장하는 것이므로 복사를 한 객체와 독립적이다.


---

#### 책 정리

**원시 타입과 참조 타입의 복사 차이**

자바스크립트에서 복사의 의미는 데이터의 종류가 원시 타입이냐 참조 타입이냐에 따라 달라진다.

- 원시 타입: 숫자, 문자열, 불리언 등은 값 자체가 복사된다. 그래서 복사본을 변경해도 원본은 영향을 받지 않는다.
- 참조 타입: 객체나 배열은 값이 아니라 힙에 있는 메모리 주소를 공유한다. `let newPerson = person`처럼 대입하면 `newPerson.name`을 바꿨을 때 `person.name`까지 함께 바뀐다.

이 문제를 해결하기 위해 얕은 복사와 깊은 복사라는 개념이 등장한다.

**얕은 복사**

얕은 복사(shallow copy)는 객체나 배열을 복사할 때 `가장 상위 레벨의 값만 복사`하는 방식이다. 원본 객체 내부의 중첩된 객체나 배열은 새로운 메모리 공간에 복사되지 않고 원본의 참조를 그대로 공유한다.

```js
const shallowCopy = { ...originalObject };

shallowCopy.age = 30;               // 원본 영향 없음
shallowCopy.address.city = '부산';   // 원본의 address.city도 '부산'으로 변경됨
```

- 스프레드 문법 `{ ...obj }`, `Object.assign()`, 배열의 `slice()`, `concat()`이 모두 얕은 복사를 수행한다.
- 깊은 복사에 비해 처리 속도가 빠르고 문법이 간단하다.
- 중첩된 객체가 없거나, 중첩된 객체가 변경되어도 문제가 없는 단순한 구조에 적합하다.

**깊은 복사**

깊은 복사(deep copy)는 `내부에 있는 모든 중첩된 객체와 배열까지 새로운 메모리 공간에 재귀적으로 복사`하는 방식이다. 원본과 복사본이 완전히 독립적이므로 한쪽을 변경해도 다른 쪽에 영향을 주지 않는다.

가장 흔하게 사용하는 방법은 `JSON.parse(JSON.stringify(obj))`이다. 객체를 JSON 문자열로 바꿨다가 다시 객체로 변환하는 과정에서 완전히 새로운 객체가 생성된다.

원본 데이터를 그대로 유지하면서 복사본을 자유롭게 수정해야 할 때, 중첩된 객체가 많거나 데이터 무결성이 중요한 경우에 필수적이다. 예를 들어 리덕스에서 상태 불변성을 유지할 때 사용된다.

**JSON 방식의 한계**

`JSON.parse(JSON.stringify())`는 간편하지만 한계가 있다.

1. Date 객체: ISO 형식의 문자열로 변환되고 다시 Date 객체로 복원되지 않는다. 그래서 `setFullYear()` 같은 Date 메서드를 쓸 수 없다.
2. 함수: JSON은 데이터 포맷이라 실행 가능한 코드를 포함하지 않으므로 함수는 제거된다.
3. undefined, Symbol: 값이 `undefined`인 속성은 속성 자체가 제거되고, Symbol 타입 속성은 무시된다.
4. 순환 참조: 자기 자신을 참조하는 구조가 있으면 `TypeError: Converting circular structure to JSON` 에러가 발생한다.
5. Map, Set, RegExp 등 내장 객체: 원래 타입으로 복원되지 않고 일반 객체나 빈 객체가 되거나 사라진다.

**안전한 깊은 복사 방법**

1. 재귀 함수 직접 구현: 객체의 모든 중첩 속성을 순회하며 복사한다. 가장 유연하지만 코드가 복잡해지고 예외 처리를 신경 써야 한다.
2. 외부 라이브러리: 로대시의 `_.cloneDeep()`이 가장 일반적이고 권장되는 방법이다. 위에서 말한 대부분의 함정을 안전하게 처리해 준다.
3. `structuredClone()`: 최신 브라우저가 제공하는 깊은 복사 내장 API로 JSON 방식의 많은 한계를 해결해 준다. Date 객체도 Date 객체로 유지된다. 다만 노드.js 초기 버전 등 일부 환경에서는 지원되지 않을 수 있다.

얕은 복사와 깊은 복사는 데이터 불변성을 유지해야 하는 리액트나 뷰 같은 프레임워크에서 더욱 중요하게 다뤄진다.

---

#### 모의 면접

**Q1: 자바스크립트에서 원시 타입과 참조 타입을 변수에 할당할 때 값이 복사되는 방식의 차이는 무엇인가요?**

> 원시 타입은 값 자체가 복사되기 때문에 복사한 변수를 바꿔도 원본은 그대로이다.  
> 참조 타입은 힙에 있는 객체의 메모리 주소를 공유하기 때문에 복사한 변수의 속성을 바꾸면 원본도 같이 바뀐다.

<br>

**Q2: 얕은 복사와 깊은 복사의 차이점과 각각의 장단점 그리고 깊은 복사를 안전하게 구현하는 방법에는 어떤 것들이 있나요?**

> 얕은 복사는 최상위 속성만 복사하고 중첩된 객체나 배열은 참조를 공유한다. 스프레드 문법이나 `Object.assign()`으로 간단하고 빠르게 구현할 수 있지만 중첩된 데이터를 수정하면 원본까지 바뀔 수 있다.  
> 
> 깊은 복사는 중첩된 객체까지 전부 새로운 메모리 공간에 복사해서 원본과 완전히 독립적이다. 대신 얕은 복사보다 비용이 크다.  
> 
> `JSON.parse(JSON.stringify())`는 간단하지만 Date, 함수, undefined, Symbol, 순환 참조 등을 처리하지 못한다. 그래서 안전하게 하려면 로대시의 `_.cloneDeep()`이나 `structuredClone()`을 사용하는 것이 좋다.

### Q41 스코프 체인이란 무엇인가요?

---

#### **책을 읽기 전 혼자 답해보기**

> 스코프 체인이란 변수나 함수는 선언될 때 해당 스코프 내에서만 사용할 수 있지만 스코프 체인을 통해 점점 더 넓은 스코프를 탐색할 수 있다. 이전 스터디인 컨텍스트 부분 정리에서 다룬 내용이다.

---

#### 책 정리

**스코프와 스코프 체인**

스코프(scope)는 `변수나 함수에 대한 유효 범위 또는 접근 규칙`을 의미한다. 변수나 함수를 선언하면 해당 스코프 내에서만 사용할 수 있다.

스코프 체인(scope chain)은 이러한 `스코프들이 계층적으로 연결되어 있는 목록 또는 연결 리스트`를 의미한다. 자바스크립트 엔진이 변수나 함수를 찾을 때 이 체인을 따라 순차적으로 검색해 나간다.  
(책을 찾을 때 내 책상 위 → 방 → 거실 → 서재 순으로 범위를 넓혀가며 찾는 것과 같다.)

**스코프 체인의 동작 원리**

함수가 호출될 때마다 실행 컨텍스트(execution context)가 생성되고, 그 안에는 렉시컬 환경(lexical environment)이 포함되어 있다. 스코프 체인은 이 렉시컬 환경들의 연결로 이루어진다.

렉시컬 환경은 2가지 요소를 가진다.

- 환경 레코드(environment record): 현재 스코프 내의 식별자(변수, 함수 선언, 매개변수 등)와 바인딩된 값을 저장한다.
- 외부 렉시컬 환경 참조(outer lexical environment reference): 현재 스코프를 감싸고 있는 상위 스코프의 렉시컬 환경에 대한 참조를 저장한다.

**변수 검색 순서**

1. 현재 스코프(자신이 속한 렉시컬 환경)에서 먼저 찾는다.
2. 없으면 외부 렉시컬 환경 참조를 따라 한 단계 상위 스코프로 이동해서 찾는다.
3. 상위 스코프에도 없으면 그 상위 스코프로 계속 이동한다.
4. 가장 상위인 전역 스코프(global scope)에 도달할 때까지 반복한다.
5. 전역 스코프에서도 찾지 못하면 `ReferenceError`가 발생한다.

```text
innerFunction scope → outerFunction scope → global scope
```

`innerFunction` 안에서 `outerVar`를 찾으면 현재 스코프에 없으니 `outerFunction` 스코프에서 찾고, `globalVar`는 전역 스코프까지 올라가서 찾는다. 어디에도 없는 변수는 `ReferenceError`가 된다.

**스코프 체인의 중요성과 영향**

- 변수, 함수 검색 원리: 변수나 함수를 참조할 때 어떤 값을 가져올지 결정하는 기본 원리이다.
- 클로저(closure): 함수는 자신이 선언될 당시의 렉시컬 환경(상위 스코프)을 기억하고 이 스코프 체인을 통해 외부 스코프의 변수에 접근한다. 그래서 `createCounter()`가 종료된 후에도 반환된 함수가 `count`에 접근할 수 있다.
- 성능: 변수가 현재 스코프에 가까울수록, 즉 체인이 짧을수록 변수 검색 성능이 좋다.

스코프 체인은 함수가 `호출된 위치`가 아니라 `선언된 위치`에 따라 결정된다. `innerFunction`이 `outerFunction` 내부에 선언되었기 때문에 상위 스코프가 `outerFunction`이 되는 것이고, 다른 곳에 선언되었다면 스코프 체인도 달라진다.

---

#### 모의 면접

**Q1: 자바스크립트에서 스코프 체인은 어떻게 구성되며 변수를 검색할 때 어떤 순서로 탐색하나요?**

> 함수가 호출되면 실행 컨텍스트가 생성되고 그 안의 렉시컬 환경이 외부 렉시컬 환경 참조로 상위 스코프와 연결되면서 스코프 체인이 구성된다.  
> 변수를 찾을 때는 현재 스코프부터 찾고 없으면 상위 스코프로 한 단계씩 올라가며 전역 스코프까지 탐색한다. 전역에서도 없으면 `ReferenceError`가 발생한다.

<br>

**Q2: 클로저가 외부 함수의 변수에 접근할 수 있는 이유는 무엇이며 스코프 체인과 어떤 관계가 있나요?**

> 함수는 선언될 당시의 렉시컬 환경을 기억하고 있기 때문에 외부 함수의 실행이 끝난 후에도 스코프 체인을 통해 외부 함수의 변수에 접근할 수 있다. 즉, 클로저는 스코프 체인 덕분에 동작하는 것이다.

### Q48 클래스를 사용하는 이유는 무엇인가요?

---

#### **책을 읽기 전 혼자 답해보기**

> 자바스크립트는 프로토타입 언어이다. 메서드의 내부를 브라우저 콘솔을 통해 하나하나 들여다본다면 프로토타입이라는 객체를 찾을 수 있다. 클래스를 사용하는 이유는 객체 지향 프로그래밍을 더 쉽게 하기 위해서이다.

---

#### 책 정리

**자바스크립트 클래스의 역사**

자바스크립트는 프로토타입 기반 언어이며 객체는 프로토타입 체인을 통해 속성과 메서드를 상속하고 공유한다. ES6(ECMAScript 2015) 이전에는 클래스 문법이 없었기 때문에 생성자 함수와 프로토타입을 조합해서 클래스와 유사한 객체 지향 패턴을 구현했다.

```js
function Person(name, age) { this.name = name; this.age = age; }
Person.prototype.sayHello = function () { ... };
```

이 방식은 클래스에 익숙한 개발자에게 낯설고 복잡했고, 특히 상속 관계를 설정할 때 가독성이 떨어지고 실수가 잦았다. 이를 해결하기 위해 ES6에서 `class` 키워드가 도입되었다.  
즉, 자바스크립트의 클래스는 기존 프로토타입 기반 상속을 더 직관적인 문법으로 사용할 수 있게 한 `문법적 설탕`이다.

**클래스를 사용하는 이유**

- 객체 지향 프로그래밍 패러다임과의 높은 유사성: 자바, C++, 파이썬 등 OOP 언어에 익숙한 개발자가 쉽게 이해하고 작성할 수 있다. 상속과 캡슐화 같은 개념을 명확하게 표현할 수 있다.
- 코드 가독성 및 유지보수성 향상: 관련 있는 속성과 메서드를 하나의 `class` 블록 안에 모아 관리할 수 있어 구조를 파악하기 쉽다.
- 상속 구현의 간결성: `extends`로 상속 관계를 쉽게 설정하고 `super`로 부모 클래스의 생성자나 메서드를 호출할 수 있다.
- 메서드 효율성: 클래스 내부에서 정의한 메서드는 자동으로 `prototype`에 추가되어 모든 인스턴스가 공유한다. 생성자 함수에서 메서드를 `this`에 직접 할당해서 인스턴스마다 메서드가 생기던 문제를 자연스럽게 해결한다.

**클래스의 한계와 주의점**

- 본질적 한계: 클래스 문법이 생겼다고 자바스크립트가 클래스 기반 언어가 된 것은 아니다. 내부적으로는 여전히 프로토타입 기반으로 동작하기 때문에 프로토타입을 이해하지 못하면 디버깅이 어려울 수 있다.
- 접근 제어자의 한계: 자바나 C++의 `private`, `protected` 같은 접근 제어자가 기본적으로 제공되지 않는다. `#`을 이용한 private 필드 문법이 추가되었지만 아직 완전히 보편화되지 않아 캡슐화를 엄격하게 강제하기에 한계가 있다.
- 호이스팅 미적용: 클래스는 함수 선언문과 달리 호이스팅되지 않는 것처럼 동작한다. `let`, `const`처럼 일시적 사각지대(TDZ)를 가지기 때문에 선언 전에 참조하면 `ReferenceError`가 발생한다.

**클래스의 사용 방법**

- 클래스 선언: `class` 키워드 뒤에 파스칼 케이스로 이름을 쓰고 중괄호 안에 생성자, 메서드, 정적 메서드를 정의한다.
  - `constructor`: 인스턴스가 생성될 때 호출되는 특별한 메서드
  - 메서드: 클래스의 프로토타입에 추가되는 공유 메서드
  - `static` 메서드: 인스턴스가 아닌 클래스 자체에 바인딩되는 메서드라 `Person.describe()`로는 호출되지만 `p1.describe()`는 에러가 난다.
- 인스턴스 생성: `new` 키워드로 클래스를 호출하면 내부적으로 새로운 객체가 생성되고 `constructor`가 자동으로 호출된다.
- 상속: `extends`로 다른 클래스를 상속받아 기존 속성과 메서드를 재사용하면서 기능을 추가하거나 변경할 수 있다. 자식 클래스에서 생성자를 정의하면 반드시 `super()`를 먼저 호출해야 한다. 부모 클래스가 초기화되어야 자식 클래스에서 `this`를 사용할 수 있기 때문이다.

클래스를 배울 때는 문법을 암기하는 것보다 `constructor`, `prototype`, `__proto__`, `extends`가 내부적으로 프로토타입과 어떻게 연결되는지 이해하는 것이 중요하다.

#### 모의 면접

**Q1: 자바스크립트 클래스와 프로토타입 기반 상속의 차이점과 관계는 무엇인가요?**

> 자바스크립트 클래스는 ES6에서 도입된 문법적 설탕으로, 내부적으로는 여전히 프로토타입 기반으로 동작한다. 기존에는 생성자 함수와 `prototype`을 직접 조작해서 상속을 구현했다면 클래스는 `extends`, `super`로 같은 동작을 더 직관적으로 작성할 수 있게 해준다.

<br>

**Q2: 클래스 문법이 제공하는 장점과 여전히 존재하는 한계는 무엇인가요?**

> 관련 속성과 메서드를 하나의 블록에 모아 가독성과 유지보수성이 좋아지고, 상속과 메서드 공유를 간편하게 구현할 수 있다.  
> 하지만 내부적으로는 프로토타입 기반이라 프로토타입을 이해해야 디버깅이 수월하고, 접근 제어자가 완전하지 않아 캡슐화를 엄격하게 강제하기 어렵다. 또한 TDZ 때문에 선언 전에 사용하면 `ReferenceError`가 발생한다.
