# 1주차 정리(Q1~Q5) - 김예원

## Q1. html이란 무엇인가?

#### **HTML**

**의미**

- Hyper Text Markup Language
- 하이퍼 텍스트: 문서와 문서를 링크로 연결하여 사용자가 다른 문서나 정보로 이동할 수 있도록 하는 개념
  - 웹에서는 수많은 문서를 서로 연결해야 했기 때문에 하이퍼텍스트가 필요했음
  - 하이퍼텍스트를 통해 여러 문서를 링크로 연결하여 하나의 정보 공간처럼 사용
- 마크업 언어: 문서의 구조와 의미를 태그라는 약속된 기호로 나타내는 것

**역할**

- 웹사이트를 구현하는 뼈대 역할 (구조를 잡는 역할)
- 문서에서 여기는 제목, 여기는 푸터, 여기는 캡션 등을 컴퓨터가 이해할 수 있게 함

**배경**

- 컴퓨터마다 문서 형식이 달라 호환이 안 되는 문제를 해결하기 위해, 웹에서 공통으로 사용하는 표준적인 마크업 언어를 만듦

**구성**

- 태그: HTML 문서에서 요소의 종류와 구조를 나타내는 문법
- 요소: 시작 태그, 내용, 종료 태그로 이루어진 하나의 단위
- 속성: 요소에 추가적인 정보나 설명 추가

**특징**

- 정보의 구조화
- 내용의 의미 부여

#### **시맨틱 HTML**

- 각 요소의 의미와 역할을 명확하게 전달하기 위해 나타난 개념
- 이를 실현하는 구체적인 방법이 시맨틱 태그를 사용하는 것
  - `div` 태그보다 `footer`, `article`, `header`와 같은 태그를 사용하는 것

**이점**

- 시맨틱 HTML을 통해 웹의 구조가 명확할수록 브라우저, 스크린 리더, 검색 엔진이 구조를 이해하기 쉬워짐
  - 검색 엔진 최적화(SEO)에 도움
  - 웹 접근성에 도움
  - 유지보수성 향상

#### **모의 면접**

**Q1**

> HTML은 웹 문서의 구조를 잡는 역할을 합니다. 건물로 비유하면 뼈대에 해당합니다. CSS는 구조화된 내용을 보기 좋게 꾸미는 역할로, 건물에 페인트를 칠하고 꾸며서 시각적으로 보기 좋게 만드는 작업에 해당합니다. JavaScript는 사이트의 동적인 동작을 담당하는데, 건물에 있는 자동문이 사람이 있을 때 자동으로 열리도록 하는 로직을 처리하는 역할이라고 볼 수 있습니다.

**Q2**

> HTML에서 시맨틱 태그를 사용하면 스크린 리더나 검색 엔진이 문서의 구조를 더 명확하게 파악할 수 있습니다. 이는 SEO와 웹 접근성을 높이는 데 도움을 줍니다.

## Q2. html의 Doctype은 어떤 역할을 하나요?

#### **Doctype**

- 브라우저에게 이 문서를 표준 모드로 처리하라고 명시하는 선언문
- html 요소가 아니므로 문서의 가장 위쪽에 명시
- HTML5부터는 간단하게 작성 가능
- 렌더링 모드
  - 브라우저가 문서를 해석할 때의 방식
  - 표준 모드: 현재의 웹 표준 방식으로 렌더링하는 모드
  - 쿼크 모드: 오래된 웹사이트의 하위 호환성을 위해 존재하는 렌더링 모드로, 과거의 비표준적인 동작을 재현하여 현재 브라우저에서도 읽히도록 하는 모드

**중요성**

- 브라우저가 표준 모드로 동작하게 하여 브라우저마다 다르게 보이는 문제를 예방
- 의도한 대로 나타나게 하기 위한 기본적인 시작점

#### **모의 면접**

**Q1**

> Doctype을 선언하면 브라우저가 웹 문서를 표준 모드로 해석하게 됩니다.

**Q2**

> 렌더링 모드에는 표준 모드와 쿼크 모드가 있습니다. 표준 모드는 현재 HTML 표준에 맞춰 문서를 해석하는 모드이고, 쿼크 모드는 예전에 작성된 웹 문서를 현재 브라우저에서도 최대한 의도대로 보이도록 하위 호환을 지원하는 모드입니다.

**Q3**

> 예전에는 Doctype을 선언하기 위해 여러 줄에 걸쳐 작성해야 했지만, HTML5부터는 문서 최상단에 한 줄만 작성하면 표준 모드로 읽도록 선언할 수 있습니다. 단순해진 이유는 HTML 버전 명시를 안해도 되기 때문입니다.

## Q3. `<head>` 태그 안에서는 어떤 태그를 사용하나요?

#### **`<head>`**

- 웹 브라우저가 html 문서를 해석하고 표시하는 데 필요한 메타데이터와 외부 정보를 담는 영역
- 문서의 정보나 설명을 담는 영역

**해당 태그 안에 들어가는 태그들**

- `<title>`: 사이트의 제목이 들어가는 태그로, 탭이나 즐겨찾기 부분에 나타남
- `<meta>`: html 문서에 대한 메타데이터(문서를 설명하는 정보)를 정의
  - 문자 인코딩
  - 뷰포트 설정
  - 문서 설명(description)
  - 작성자
  - 미리보기(오픈 그래프) 
- `<link>`: 현재 문서와 외부 리소스와의 관계를 정의하는 태그
  - `rel` 속성으로 해당 파일이 어떤 종류의 파일인지 명시 (css면 `stylesheet`, 파비콘이면 `icon`)
- `<style>`
  - HTML 문서 내부에 css를 직접 작성하고 싶을 때 사용, 보통은 외부에 정의하고 `<link>`를 사용
- `<script>`
  - 자바스크립트 파일과 연결하는 태그
  - `</body>` 직전에 배치하면 구조 파악 후 자바스크립트를 실행하여 렌더링 성능이 높아짐

**중요성**

- 문서의 문자 인코딩, 화면 표시 방식, 설명 등의 정보를 설정하기 때문에 페이지가 올바르게 동작하는 데 중요
- 문서 제목, 설명, 오픈 그래프 등의 메타데이터를 통해 검색 엔진 등에 도움을 줌

#### **모의 면접**

**Q1**

> `title`은 문서의 제목을 나타내는 태그로, 탭이나 즐겨찾기에 표시됩니다. `meta`는 문서의 메타데이터를 정의하는 태그로 뷰포트, 오픈 그래프, 문자 인코딩 등을 설정할 수 있습니다. `link`는 외부 리소스와 연결해주는 태그로, `rel` 속성을 통해 해당 리소스가 어떤 종류인지 나타냅니다. `style`은 css를 html 문서 내부에 직접 작성할 때 사용하는 태그입니다. `script`는 자바스크립트 파일을 html 문서에 연결하기 위한 태그입니다.

**Q2**

> `head` 태그에 들어가는 메타데이터 덕분에 문서 제목, 설명, 오픈 그래프 데이터 등을 통해 검색 엔진 최적화에 도움이 됩니다. 뿐만아니라 사용자가 검색된 결과나 공유된 콘텐츠를 보고 페이지를 파악하는데 도움을 주기 때문에 사용자 경험 측면에도 도움을 줍니다.

## Q4. 시맨틱 태그란 무엇이고, 사용하는 이유를 설명할 수 있나요?

#### **시맨틱 태그**

- 콘텐츠의 역할과 의미를 명확하게 전달하기 위한 태그

**종류**

- `header`: 머리말 부분으로 로고, 제목, 검색창 등이 들어가는 요소
- `footer`: 문서의 하단 영역으로, 저작권, 연락처 등이 들어가는 요소
- `nav`: 네비게이션 링크를 모아놓은 영역 
- `main`: 문서의 메인 영역 (한 문서에서 한 번만 사용)
- `article`: 다른 콘텐츠와 독립적으로 존재할 수 있는 콘텐츠 (뉴스 기사)
- `section`: 연관된 콘텐츠를 하나의 주제로 그룹화할 때 사용
- `aside`: 주요 콘텐츠와 직접적인 관련은 없지만 부가적인 정보를 제공 (사이드바, 광고)

**역할**

- 검색 엔진 최적화(SEO)에 도움 
- 웹 접근성 향상 
- 유지보수성 향상

#### **모의 면접**

**Q1**

> 시맨틱 태그를 사용하면 검색 엔진과 스크린 리더가 문서 구조를 파악하기 쉬워져서 검색 엔진 최적화에 도움이 되고, 웹 접근성도 함께 향상됩니다.

**Q2**

> `div`는 단순히 구조만 분리할 뿐, 어떤 내용이 들어있는지는 직접 내용을 읽어봐야 알 수 있습니다. 반면 시맨틱 태그를 사용하면 태그만 보고도 어떤 내용이 들어갈지 유추할 수 있어 유지보수 측면에서 유리합니다.

## Q5. 웹 표준과 웹 접근성이란 무엇인가요?

#### **웹 표준**

- 웹 사이트를 만들 때 사용하는 공통적인 기술 규칙이자 표준
- W3C에서 제정

**왜 따라야 하나**

- 웹 호환성 때문
  - 표준을 준수하면 브라우저마다 html과 css를 해석하는 방식을 동일하게 해줘서 호환성 문제를 해결할 수 있음
- 그 밖에도 검색 엔진 최적화, 유지보수에 도움

**어떻게 따르나**

- 표준 문법 사용
- 시맨틱 태그 사용

#### **웹 접근성**

- 장애 여부나 환경에 상관없이 모든 사용자가 동일한 웹 콘텐츠와 기능을 사용할 수 있도록 하는 것

**어떻게 따르나**

- 스크린 리더(화면 정보를 읽어주는 소프트웨어)가 구조와 의미를 잘 이해할 수 있도록 작성
- 이미지에 텍스트 제공
  - `alt` 속성을 주면 스크린 리더가 이미지를 읽을 수 있음
- 키보드만으로 접근 가능하게 하기
  - `div` 태그는 키보드 포커스를 받지 못하므로 명확한 시맨틱 태그 사용
- 충분한 색상 대비 제공

#### **모의 면접**

**Q1**

> 웹 표준은 웹사이트를 만들 때 공통으로 사용하는 규약으로, 모두가 동일한 규칙으로 구조를 작성하게 하여 웹 호환성을 높이기 위한 것입니다. 웹 접근성은 장애 여부나 환경에 상관없이 모든 사용자가 동일한 콘텐츠와 기능을 사용할 수 있도록 하는 것입니다.

**Q2**

> 이미지에 대체 텍스트를 제공하여 스크린 리더가 이미지를 읽을 수 있게 하고, 충분히 대비되는 색상을 사용합니다. 또한 마우스뿐 아니라 키보드만으로도 요소에 접근할 수 있도록 시맨틱 태그를 사용하는 방법이 있습니다.
