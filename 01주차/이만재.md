### Q1 HTML이란 무엇인가요?

---

#### **책을 읽기 전 혼자 답해보기**

> HTML은 HyperTextMarkupLanguage의 줄임말이며, 웹페이지의 기본이 되는 뼈대를 구축하는데 사용되는 언어이다.  
> HTML이 프로그래밍 언어인가? 라고 하면 그렇지 않다 프로그래밍 언어라고 하면 함수를 작성할 수 있어야하고 그 함수를 동작시키는 등의 기능이 필요하다.  
> 하지만 마크업 언어인 HTML 화면의 뼈대를 잡을 순 있지만 HTML 언어만으로 함수를 작성하거나 동작시킬 수 없다.  
> 
> HTML은 많은 태그가 있지만(div, p, a 등) 그 중 시맨틱 태그라고 불리는 태그들이 있다.  
> 이 태그들은 `<head>` `<footer>` `<section>` 등이 있으며 이 태그들을 통해 스크린 리더는 화면 레이아웃이 어떻게 구성되어있는지 파악할 수 있다.  
> 사실 사람이 보기에 div 태그로만 화면 레이아웃을 구성해도 보기에는 시맨틱 태그들을 잘 구조화해서 한 것과 똑같아 보일 것이다.  
> 하지만 스크린 리더 입장에서는 다르다.  
> 스크린 리더는 HTML을 읽을 때 시맨틱 태그들을 통해서 지금 여기 영역히 화면의 head구나 footer구나 하고 알 수 있기 때문이다.  
> 
> 웹 접근성, SEO를 한 번쯤 다들 들어봤을 것이다.  
> 이 웹 접근성과 SEO 최적화에 가장 기본이자 중요한 것이 시맨틱 태그들을 잘 활용해 구조화하는 것이다.  
> 검색 엔진에 우리의 사이트가 잘 노출되려면 시맨틱 태그들로 구성이 되어있어야 스크린 리더가 사이트를 이해할 수 있고 이는 곳 검색 노출 상위에 노출시키기 쉽다는 뜻이기도 하다.  
> 그렇기 때문에 홍보성을 가진 사이트이거나 공식 홈페이지 등 연관 검색어와 연결되어 노출하려면 SEO, GEO 등 웹 접근성에서도 신경을 많이 써야한다.  

---

#### **책 정리**

1989년 팀 버너스리가 전 세계 연구자가 정보를 쉽게 공유할 수 있도록 웹을 만들었다.  
당시에는 컴퓨터 시스템과 플랫폼마다 사용하는 문서 형식이 달라서 불편했고 이를 해결하기 위해 설계한 마크업 언어가 HTML이다.  
수학 기호나, 음악 기호처럼 사용하는 언어가 달라도 보편적인 표기체계는 이해할 수 있듯이 플랫폼에 상관없이 모든 컴퓨터가 동일하게 읽을 수 있는 형식을 제공한 것이다.  
HTML이란 의미를 담은 정보의 뼈대로 단순히 콘텐츠를 표시하는 것을 넘어 정보에 구조와 의미를 부여한다.  

- **하이퍼텍스트**: 특정 단어나 문장에 링크를 부여해 다른 문서나 페이지로 즉시 이동할 수 있게 만든 텍스트를 말한다. 웹에서 링크를 클릭해 이동하는 모든 행위가 하이퍼텍스트의 원리를 이용하는 것이다. 하이퍼텍스트는 웹의 가장 큰 특징인 연결성을 구현하는 핵심 개념
- **마크업**: ‘표시하다’라는 의미로 문서의 구조와 의미를 태그라는 약속된 기호를 사용해 표시하는 방식이다. 예를 들어 글자를 굵게 만드는 스타일인 font-weight을 적용하는 것은 시각적인 효과만 줄 뿐이지만 strong태그를 사용하면 중요한 정보라는 의미 자체를 웹 브라우저에게 전달할 수 있다.

##### HTML의 구조: 태그, 요소, 속성
HTML 문서는 요소의 집합으로 이루어지며 요소는 태그로 표현된다.  
요소에 추가 정보나 기능을 부여할 때는 속성을 사용한다.  

```html
<a href="https://www.naver.com">네이버</a>
```

위 코드에서 요소는 `<a/>`이고 속성은 href이며 그 값은 "https://www.naver.com"이다.  

##### HTML의 역할: 정보 구조화와 의미 표시
HTML이 웹에서 담당하는 역할이 정보의 구조화이다.  
여기서 더 중요한 핵심은 의미를 표시하는 것이다.  
단순히 글자를 크거나 굵게 보이게 하는게 아닌 이것은 제목이다. 이것은 메뉴 항목이다처럼 각 요소의 역할과 의미를 태그로 알려준다.  

##### HTML의 진화: 시맨틱과 웹 접근성
초기HTML은 문서의 구조를 표현하는데 집중했다.  
웹이 발전하면서 각 요소의 의미를 명확하게 전달하는 것이 중요해졌고 이 과정에서 시맨틱 HTML이라는 개념이 등장했다.  
이를 실천하는 구체적인 방법이 시맨틱 태그이다.  
시맨틱 태그는 태그 이름만으로도 해당 영역의 역할을 알 수 있게해준다.  
그렇기 때문에 의미에 맞는 시맨틱 태그를 사용하면 검색 엔진이나 스크린 리더같은 기기도 웹 사이트의 구조를 정확이 이해할 수 있어 검색 엔진 최적화와 웹 접근성에 매우 중요한 요소이다.  

현재 웹 표준인 HTML5는 이런 시맨틱 웹의 철학을 적극적으로 반영한다.  
`<head>`, `<footer>`, `<nav>`, `<article>`, `<section>` 등 다양한 시맨틱 태그를 추가해 문서 구조를 더 명확하게 표현할 수 있게 했으며 별도의 플러그인 없이 비디오, 오디오를 재생할 수 있는 `<video>`, `<audio>` 웹에서 그래픽을 직접 그릴 수 있는 `<canvas>` 등 여러 기능으 대거 도입되어 웹의 표현력은 높였다.

> 또한 이런 시맨틱 태그 활용과 메타데이터 설정은 웹 접근성과 검색엔진최적화에도 유리하다.  
> 한 줄로 정리하자면 웹 브라우저가 내 사이트의 구조를 정확히 이해할 수 있게할 때 웹 접근성, 검색엔진최적화에 용이하고 이를 위해서 시맨틱 태그가 필요하다.

### Q2 HTML의 Doctype은 어떤 역할을 하나요

---

#### **책을 읽기 전 혼자 답해보기**

> HTML 기본 구조를 만들 때 사용한다, 아마 기억에 가장 최신의 HTML 버전을 사용한다는 의미라고 알고있음

---

#### 책정리

HTML 문서 맨 첫 줄에는 항상 `<!DOCTYPE>`이라는 키워드가 선언되어있다.

##### Doctype의 의미와 역할

Doctype 선언은 문서 형식 선언으로 웹 브라우저가 HTML 문서를 어떤 버전으로 해석해야 하는지 알려주는 선언문이다. 
웹 브라우저는 Doctype 선언을 기준으로 렌더링 모드를 결정하는데 렌더링 모드는 표준 모드와 쿼크 모드로 나뉜다.

- **표준모드**: W3C나 WHATWG 같은 웹 표준을 최대한 정확하게 준수하여 렌더링 하는 모드로, 우리가 기대하는 방식대로 CSS와 레이아웃이 적용된다. HTML5의 `<!Doctype html>`은 웹 브라우저를 표준모드로 동작하게 한다.
- **쿼크모드**: 오래전에 만들어져 현재의 표준을 따르지 않는 웹 사이트가 최신 웹브라우저에서도 깨져 보이지 않도록 지원하는 하위 호환성 렌더링 모드이다. Doctype이 선언되지 않거나 잘못 선언되면 웹 브라우저는 문서가 예전 방식으로 만들어졌다고 판단하여 쿼크모드로 렌더링한다. 이 모드에서는 CSS 해석 방식이 달라져 웹 브라우저마다 결과가 다르게 보이거나 의도와 다르게 레이아웃이 구성될 수 있다.

---

> Doctype 선언이 되어있는 경우 웹 브라우저는 가장 최신인 웹 표준(HTML5)를 따른다고 생각하고 표준 모드로 렌더링한다. 하지만 선언이 되어있지 않거나 선언이 잘못된 경우 하위 호환 모드인 쿼크모드로 렌더링하는데 이때는 CSS 해석 방식이 달라져 웹 브라우저마다 결과가 다르게 보이거나 의도와 다르게 레이아웃이 구성될 수 있다.

### Q3 `<head>` 태그 안에는 어떤 태그를 사용하나요?

---

#### **책을 읽기 전 혼자 답해보기**

> title, meta 태그 정도가 생각난다. title은 사이트의 이름이고 meta 태그는 인코딩 형식이랑 뷰포트 등 기본 설정들이 들어있다.

---

#### 책 정리

##### `<head>` 태그: 웹 사이트의 설명서

`<head>` 태그는 웹 브라우저에 문서의 특징, 필요한 파일, 해석 기준을 알려주는 설명서로 웹 사이트의 정체성을 정의하는 메타데이터를 담는 공간이다. 화면에 보이지는 않지만 웹 사이트의 동작과 검색 엔진 최적화에 아주 결정적인 역할을 한다.

##### `<title>` 태그: 웹 사이트의 이름표 

`<title>` 태그는 웹 브라우저의 탭이자 즐겨찾기에 표시되는 웹 사이트의 제목을 정의한다. 

##### `<meta>` 태그: 웹 사이트의 상세 정보

`<meta>` 태그는 웹 사이트의 다양한 정보를 담을 수 있는 만능 태그로 속성에 따라 웹 브라우저나 검색 엔진이 웹 사이트를 어떻게 이해할지 결정됩니다. 대표적인 속성으로 viewport, description, og등이 있습니다. 

- 문자인코딩: 문서에서 어떤 문자 인코딩을 사용하는지 알려주고 UTF-8로 지정해야 한글이나 여러 나아 언어가 깨지지 않고 표시된다.
- 뷰포트 설정: 스마트폰, 태블릿 등 다양한 기기에서 웹 사이트의 너비와 배율을 어떻게 표시할 지 결정한다.
- 웹 사이트 요약: 웹 사이트의 핵심 내용을 요약하며 사용자가 웹 사이트의 내용을 빠르게 파악하는데 도움이 되며 클릭을 유도하는데 중요한 역할을 한다.
- 작성자 정보: 페이지의 작성자 정보를 담고 있으며 검색 엔진이나 문서 관리 도구에서 웹 사이트의 소유자를 확인할 때 사용한다.
- 미리보기: 카카오톡이나 페이스북, X와 같은 소셜 미디어에 웹 사이트 링크를 공유할 때 해당 웹 사이트의 제목, 설명, 대표 이미지 등이 표시되도록 설정하는 기능이다. (오픈그래프, 트위터카드) 가 대표적이다.

##### `<link>` 태그: 외부 파일 연결

웹 사이트는 HTML만으로 완성되지 않고 CSS파일, 파비콘 등 외부에서 가져와 연결해야하는 요소가 많다 이때 HTML의 `<link>` 태그를 사용한다.

- CSS 파일 연결: 외부 CSS 파일에 연결하여 웹 페이지의 디자인과 레이아웃을 꾸밀 때 사용하는 태그이다.
- 파비콘 설정: 웹 브라우저 탭에 표시되는 작은 아이콘인 파비콘을 설정할 때 사용한다.

##### `<style>` 태그: 내부 스타일 시트

HTML 문서 내부에서 CSS 코드를 직접 작성하고 싶을 때 사용한다.

##### `<script>` 태그: 자바스크립트 연결

웹 페이지에 동적인 기능을 추가하는 자바스크립트 파일을 연결하거나 내부에 코드를 직접 작성할 때 사용한다.

#### 모의 면접

**Q1: `<head>` 태그 안에 자주 사용하는 주요태그 `<title>`, `<meta>`, `<link>`, `<style>`, `<script>`는 각각 어떤 역할을 하나요?**

> title 태그는 사이트의 이름을 표기하는 태그  
> 
> meta 태그는 사이트의 정보를 담고있는 태그이며 문자 인코딩, 뷰포트 설정, 웹 사이트 요약, 작성자 정보, OG이미지 등이있다.  
> 
> link 태그는 외부 파일을 연결할 때 사용한다.  
> 
> sytle 태그는 html 내부에 스타일 코드를 작성할 때 사용한다.  
> 
> script 태그는 자바스크립트 파일을 연결하거나 간단한 자바스크립트 코드를 바로 작성해서 동작을 확인해볼 때 사용한다.  

<br />

**Q2: `<head>` 태그의 설정은 검색 엔진 최적호와 사용자 경험(UX)에 왜 중요한 영향을 미치나요?**

> head 태그에는 웹 사이트가 무슨 정보를 담고있는지 나타내는 태그들이 모여있다. 이 정보들을 웹 브라우저와 스크린 리더 같은 기기들이 읽어서 사이트를 정확히 파악할 수 있고 이는 곳 검색 엔진 최적화로이어진다. 또한 사용자 역시 사이트에 대한 정보를 쉽게 확인할 수 있기 때문에 UX적인 측면에서도 필요하다.

### Q4 시맨틱 태그란 무엇이고, 사용하는 이유를 설명할 수 있나요?

---

#### **책을 읽기 전 혼자 답해보기**

> 시맨틱 태그란 웹 브라우저와 스크린 리더와 같은 기기들이 웹 사이트의 구조와 정보를 정확히 파악할 수 있도록 하기 위해 사용하며 의미와 정보를 가지고 있는 태그들을 말한다. 예시로 head, nav, aside, section 등이 있다.

---

#### 책정리

과거에는 웹 사이트 구조를 대부분 `<div>` 태그로 만들었다. 하지만 div 태그는 영역을 나누는 용도만 있을 뿐, 의미가 없는 비 시맨틱 태그이다. HTML5가 등장하면서 의미를 지닌 시맨틱 태그가 표준으로 자리 잡았다. 시맨틱 태그란 이름만으로도 콘텐츠의 역할과 의미를 명확하게 전달하는 HTML 태그를 말한다.

- `header`: 웹 사이트나 특정 섹션의 머리말을 나타낸다. 로고, 제목, 검색 창 등의 정보가 들어간다.
- `footer`: 웹 사이트나 특정 섹션의 꼬리말 영역을 나타낸다. 저작권 정보, 연락처 등부가 정보가 포함된다.
- `nav`: 다른 웹사이트로 이동하기 위한 내비게이션 메뉴를 묶을 때 사용한다.
- `main`: 문서의 핵심 콘텐츠를 담는다. 이 태그는 문서에 단 한 번만 사용해야한다.
- `article`: 블로그 글, 뉴스 기사 등 독립적인 콘텐츠를 담는다.
- `section`: 연관 콘텐츠를 그룹화할 때 사용한다. 보통 제목을 함께 포함한다.
- `aside`: 사이드바나 광고 등 문서의 주요 내용과 간접적으로 연관된 정보를 담는다.

##### **시맨틱 태그의 역할**

시맨틱 태그는 이름 자체로 콘텐츠릐 의미와 역할을 전달한다. 아래 3가지 측명에서 중요한 역할을 한다.

1. 검색 엔진 최적화: 구글, 네이버 같은 검색 엔진은 크롤러 같은 로봇을 활용해 웹 사이트 정보를 수집하는데 이 로봇은 div 태그보다 시맨틱 태그로 구성된 웹 사이트를 더 정확하게 이해하고 main과 article 태그 내의 내용을 핵심 콘텐츠로 파악하여 검색 결과에 더 높은 가중치를 부여할 수 있다.
2. 웹 접근성 향상: 시각 장애인은 웹을 이용할 때 화면의 내용을 음성으로 읽어주는 스크린 리더라는 프로그램을 사용한다, 시맨틱 태그는 스크린 리더가 페이지의 구조를 파악하는 중요한 역할을 한다. 불필요한 영역이라면 건너뛰고 main 태그인 본문으로 이동할 수 있게 돕는다.
3. 코드의 유지보수 효율 향상: div 태그로만 이루어진 코드보다 시맨틱 태그로 작성된 코드가 문서의 구조를 한 눈에 알아보기 쉬워 효율적이다.

---

#### 모의 면접

**Q1: `<header>`, `<main>`, `<article>`과 같은 시맨틱 태그를 사용하면 검색 엔진 최적화와 웹 접근성에 어떤 이점이 있을까요?**

> 검색 엔진 사이트(구글,네이버)에서는 크롤러 로봇을 통해 웹 사이트의 정보를 수집하는데 이때 로봇이 비 시맨틱 태그로 이루어진 사이트보다 main, article 태그 안에 내용을 핵심 정보로 판단해 검색 결과에 가중치를 부여할 수 있다. 웹 접근성의 경우 시각 장애인들은 스크린 리더라는 기기를 통해 웹 사이트를 사용하는데 이때 태그가 가진 의미를 통해 스크린 리더가 웹 사이트를 명확히 이해할 수 있으며 불필요할 경우 건너뛰기를 통해 바로 main의 핵심 내용으로 넘어갈 수 있다.

<br />

**Q2: `<div>` 태그 대신 시맨틱 태그를 사용하는 것이 코드 가독성과 유지 보수성 측면에서 왜 더 유리할까요?**

> div 태그로만 이루어진 코드는 개발자가 id나 class 이름을 통해 영역을 구분해야하지만 시맨틱 태그를 통해 잘 구조화된 코드는 문서의 구조가 한 눈에 들어오기 때문에 더 효율적이기 때문이다.

### Q5 웹 표준과 웹 접근성이란 무엇인가요?

---

#### **책을 읽기 전 혼자 답해보기**

> 웹 표준은 현대의 웹이 따라야하는 표준을 의미하고 웹 접근성은 장애인, 노약자 등 누구나 불편 없이 웹 서비스를 이용할 수 있는 것을 의미한다.

---

#### 책정리

##### **웹의 헌법, 웹 표준**

웹 표준은 W3C 같은 공식 표준화 기구가 제정하 웹 기술의 공식 규약이다. 쉽게 말해 웹 사이트를 만들 때 따라야하는 공통 규칙을 전 세계가 합의한 것으로 웹의 헌법이라고 할 수 있다.

그렇다면 이런 규칙이 왜 필요한걸까? 이유는 웹 호환성 때문이다. 사용자가 크롬, 사파리 등 어떤 웹 브라우저로 접속하든, 웹 사이트는 동일하게 보이고 정상으로 작성하는 것이 웹 표준의 핵심 목표이다. 

##### **웹 표준을 준수하면 얻는 이점** 

- 호환성 확보: 웹 브라우저별 대응에 드는 개발 비용과 시간을 크게 줄일 수 있다.
- 유지보수 효율 향상: 규칙에 따라 잘 정돈된 코드는 수정과 기능 확장이 쉽다.
- 검색 엔진 최적화: 검색 엔진은 웹 표준을 준수한 웹 사이트의 구조를 더 정확히 이해해 검색 순위 향상에 긍정적인 영향을 준다.

##### **모두를 위한 기술, 웹 접근성**

웹 표준이라는 훌륭한 설계도에 따라 건물을 지었다면 이제 누가 이 건물을 사용할지를 고민해야 한다. 여기서 등장하는 개념이 웹 접근성이다.

웹 접근성은 사용자의 장애 여부나 이용 환경에 관계없이 누구나 웹 콘텐츠를 똑같이 인식하고 사용할 수 있도록 보장하는 원칙이다.

##### **웹 접근성을 높이기 위한 3가지 구체적인 예시**

- 이미지 대체 텍스트 제공하기: 스크린 리더는 화면 정보를 음성으로 읽어주는 소프트웨어이다. 사용자가 시각 장애가 있을 경우 스크린 리더는 이미지를 만나면 alt 속성에 담긴 텍스트를 대신 읽어준다. 만약 alt가 비어있다면 사용자는 해당 위치에 어떤 정보가 있는지 알 수 없다.
- 키보드만으로 모든 기능에 접근할 수 있게하기: 링크, 버튼, 입력 창 등 모든 상호작용 요소는 마우스 없이도 키보드만으로 접근하고 실행할 수 있어야 한다. 이는 마우스를 사용하지 못하는 사용자뿐 아니라 키보드 사용을 선호하는 사용자에게도 필수적인 기능이다.
- 충분한 색상 대비 제공하기: 저시력자나 색각 이상 소유자를 고려해 텍스트와 배경색은 충분히 대비 되어야한다.

#### 모의 면접

**Q1: 웹 표준과 웹 접근성의 차이점과 각각의 목적은 무엇인가요.**

> 웹 표준은 웹 사이트를 만들 때 꼭 지켜야하는 약속이며 사용자가 어떤 브라우저에서 접속해도 같은 웹 사이트를 보게 하는 것이 목표이다. 웹 접근성은 장애, 노약자 등 모두가 공평하게 웹 사이트를 이용할 수 있도록 하는 것이며 웹 표준을 잘 지키는 것은 곧 웹 접근성을 고려하는 가장 쉬운 방법이다.

<br />

**Q2: 웹 접근성을 높이기 위해 HTML에서 적용할 수 있는 구체적인 방법 3가지는 무엇인가요?**

> 1. 이미지 대체 텍스트 지정하기: 시각 장애를 가지고 있거나 네트워크 문제로 이미지를 다운 받지 못할 때 alt에 적어둔 대체 텍스트를 확인하는데 이때 alt가 비어있으면 사용자는 해당 위치에 어떤 정보가 있는지 알 수 없다.  
> 2. 키보드 접근성 고려하기: 마우스 사용이 불편하거나 키보드 사용을 선호하는 경우를 고려하여 키보드 만으로도 링크, 버튼 등 상호작용하는 요소에 접근이 가능해야한다.   
> 3. 색상 대비 확보: 저시력자이거나 색각 이상이 있는 소유자를 고려해 배경색과 텍스트의 색은 충분히 대비되어야 한다.
